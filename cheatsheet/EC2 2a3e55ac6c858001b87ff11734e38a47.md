## 🧭 **Purpose**

Amazon **EC2 (Elastic Compute Cloud)** provides **resizable virtual servers** in the AWS Cloud. It offers full control over compute, networking, and storage resources, enabling you to run applications with flexible scalability and control.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Instance Types** | Different families (e.g., T for general purpose, M for balanced, C for compute-optimized). |
| **AMIs (Amazon Machine Images)** | Templates defining the OS, software, and configuration for launching instances. |
| **EBS (Elastic Block Store)** | Persistent block storage for EC2. |
| **Instance Store** | Temporary block storage physically attached to the host (lost when stopped). |
| **Placement Groups** | Determine how instances are physically placed (Cluster, Spread, Partition). |
| **Elastic IPs** | Static public IPs for persistent access. |
| **User Data & Metadata** | Configuration and automation scripts at instance launch. |
| **Elastic Network Interfaces (ENIs)** | Secondary network interfaces for multi-homed setups. |
| **EC2 Instance Connect / Session Manager** | Secure access without SSH key distribution. |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Launch multiple web servers with predictable capacity | Use **On-Demand Instances** or **Auto Scaling Groups** |
| Host a steady, always-on application | Use **Reserved Instances** or **Savings Plans** |
| Run batch processing or CI/CD jobs | Use **Spot Instances** (cost-effective, interruptible) |
| Isolate critical workloads on dedicated hardware | Use **Dedicated Hosts/Instances** |
| Enable secure SSH-free access to EC2 | Use **Session Manager** or **EC2 Instance Connect** |
| Improve fault tolerance | Deploy instances across **multiple AZs or Spread Placement Groups** |
| Low-latency cluster computing | Use **Cluster Placement Groups** |
| Need fast recovery from AMI template | Launch new instances from **custom AMIs** |
| Control startup automation | Use **User Data scripts** to configure at boot |
| Optimize performance for heavy I/O | Use **EBS-optimized instances** or **Instance Store** |

## 🔐 **Security Considerations**

- Apply **IAM roles** instead of static credentials.
- Restrict access via **Security Groups** and **Network ACLs**.
- Encrypt EBS volumes and snapshots using **KMS**.
- Disable public IPs for internal instances.
- Use **private subnets** for backend workloads.
- Log API calls using **CloudTrail**.

---

## 💲 **Pricing Model**

| Option | Description | Best For |
| --- | --- | --- |
| **On-Demand** | Pay per second/hour, no commitment. | Short-term workloads. |
| **Reserved Instances** | 1–3 year commitment for up to 72% discount. | Steady workloads. |
| **Savings Plans** | Flexible compute savings model. | Mixed compute environments. |
| **Spot Instances** | Up to 90% discount, can be interrupted. | Batch, fault-tolerant jobs. |
| **Dedicated Hosts** | Physical isolation. | Compliance/BYOL needs. |
| **Capacity Reservations** | Guaranteed capacity in an AZ. | Regulated or critical workloads. |

## 🔗 **Integration Patterns**

- **With Auto Scaling Groups** → Dynamic scaling based on demand.
- **With ELB (ALB/NLB)** → High availability and traffic distribution.
- **With CloudWatch** → Performance metrics and alerts.
- **With Systems Manager** → Automation and patching.
- **With VPC** → Network isolation and routing control.
- **With EBS/EFS/S3** → Persistent or shared storage integration.

---

## 🧠 **Exam Tips**

✅ EC2 = “**flexible compute with full control**.”

✅ **EBS = persistent**, **Instance Store = ephemeral**.

✅ **User Data** executes once per boot; **Metadata** provides instance info.

✅ **Spread** groups = resilience; **Cluster** = low latency; **Partition** = distributed workloads.

✅ Combine **Spot + On-Demand** for cost optimization.

✅ For HA, deploy across **multiple AZs**.

✅ Always use **IAM roles**, never hardcoded credentials.

## 🏁 **Real-World Example**

**Scenario:**

An e-commerce platform experiences unpredictable traffic spikes during sales events.

**Solution:**

- Deploy web servers on **EC2** behind an **Application Load Balancer**.
- Use **Auto Scaling Groups** for elasticity.
- Store media in **S3** and sessions in **ElastiCache**.
- Use **Savings Plans** for base capacity and **Spot Instances** for surge handling.

**Outcome:**

Scalable, fault-tolerant, and cost-optimized infrastructure.
