*(Protect web applications and infrastructure from DDoS and web exploits)*

**Exam Domains:**

---

## 🧭 **Purpose**

**AWS Shield** and **AWS Web Application Firewall (WAF)** work together to protect your applications from **DDoS attacks** and **common web vulnerabilities** such as SQL injection, XSS, and malicious bots.

Shield defends **infrastructure layers (L3/L4)**, while WAF protects **application layers (L7)**.

---

## ⚙️ **Key Features**

### 🔰 AWS Shield

| Feature | Description |
| --- | --- |
| **Always-On Protection** | Automatically protects AWS resources from network and transport layer DDoS attacks. |
| **Two Tiers** | **Shield Standard (free)** and **Shield Advanced (paid)**. |
| **Shield Standard** | Included by default for all AWS customers — protects against common volumetric and state-exhaustion attacks. |
| **Shield Advanced** | Adds enhanced detection, 24/7 DDoS Response Team (DRT), cost protection, and real-time metrics. |
| **Integration** | Works with CloudFront, Route 53, ALB/NLB, and Global Accelerator. |
| **DDoS Cost Protection** | Reimburses scaling or bandwidth charges from attack-related usage (Shield Advanced only). |
| **Global Threat Dashboard** | Visibility into attack metrics via AWS console. |

### 🧱 AWS WAF

| Feature | Description |
| --- | --- |
| **Layer 7 Web Firewall** | Protects HTTP/S traffic against SQLi, XSS, and custom-defined exploits. |
| **Rule-Based Filtering** | Block, allow, or count requests based on patterns (IP, headers, URI, query string). |
| **Managed Rule Groups** | Prebuilt AWS and partner security rule sets (e.g., OWASP Top 10). |
| **Custom Rules** | Build your own rules using conditions and logical combinations. |
| **Rate-Based Rules** | Throttle IPs that exceed a threshold request rate. |
| **Bot Control & Account Takeover Prevention** | Protects against bad bots and credential stuffing (advanced features). |
| **Integration** | Works with CloudFront, ALB, API Gateway, and AppSync. |
| **Logging & Metrics** | Real-time logging to CloudWatch, S3, or Kinesis Firehose. |

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Protect a CloudFront-distributed web app from DDoS | Use **Shield Standard (default)** |
| Protect ALB-based APIs from L7 web exploits | Deploy **AWS WAF WebACL** with managed rule groups |
| Add protection against volumetric DDoS attacks | Enable **Shield Advanced** on ALB, CloudFront, or Route 53 |
| Prevent SQL injection and XSS in web apps | Use **AWS WAF Managed Rules** |
| Limit request floods (rate-limiting) | Use **WAF rate-based rules** |
| Stop credential stuffing or bots | Enable **AWS WAF Bot Control** |
| Gain 24/7 DDoS incident response | Subscribe to **Shield Advanced** for DRT support |
| Protect against unexpected DDoS cost spikes | Use **Shield Advanced with DDoS Cost Protection** |
| Monitor traffic for blocked/allowed requests | Stream **WAF logs** to **Kinesis Firehose** or **CloudWatch** |
| Secure APIs behind API Gateway | Associate **WebACL** with API Gateway stage |

## 🔐 **Security Considerations**

- Shield Standard is **always active** and **requires no setup**.
- **Shield Advanced** integrates with **AWS WAF**, **CloudFront**, **ALB**, **NLB**, and **Route 53**.
- Use **WAF rule groups** (e.g., AWSManagedRulesCommonRuleSet) for common exploits.
- **Combine WAF + Shield Advanced** for layered protection (defense-in-depth).
- Enable **logging and monitoring** with CloudWatch metrics and alarms.
- For compliance, maintain **WAF logs** and **CloudTrail audit trails**.
- Use **AWS Firewall Manager** to deploy WAF/Shield policies across multiple accounts.

| Service | Cost | Notes |
| --- | --- | --- |
| **Shield Standard** | Free | Enabled automatically on all AWS endpoints |
| **Shield Advanced** | ~$3,000/month per organization | Adds DRT, cost protection, and advanced analytics |
| **AWS WAF** | Pay per WebACL, rule, and request | ~$5/WebACL/month + $1/rule + request fees |
| **Firewall Manager** | No extra cost (beyond WAF/Shield charges) | Centralized multi-account policy management |

## 🔗 **Integration Patterns**

- **CloudFront:** Combine with WAF and Shield for global web protection.
- **ALB / API Gateway:** Deploy WAF WebACLs for application-layer filtering.
- **Route 53:** Shield protects DNS layer.
- **Global Accelerator:** Enhance latency and DDoS resilience.
- **Firewall Manager:** Apply org-wide WAF and Shield policies.
- **CloudWatch & CloudTrail:** Logging, metrics, and alerting.

## 🧠 **Exam Tips**

✅ **Shield Standard** is **always on** and **free**.

✅ **Rate-based rules** in WAF mitigate brute-force or bot traffic.

✅ **Shield Advanced** includes **real-time DDoS metrics and support**.

## 🏁 **Real-World Example**

**Scenario:**

A financial web app is hosted behind an **Application Load Balancer** and **CloudFront**, serving global users. It must protect against DDoS attacks, SQL injection, and credential stuffing.

**Solution:**

- **CloudFront Distribution** → Edge caching and performance.
- **Shield Standard** (default) → Network/transport DDoS protection.
- **AWS WAF WebACL** → Enable **AWS Managed Rules** and **Rate-Based Rules**.
- **Shield Advanced** → Cost protection + 24/7 DDoS Response Team.
- **Firewall Manager** → Deploy consistent WAF rules across multiple accounts.
- Monitor security metrics via **CloudWatch** and **AWS Security Hub**.

**Outcome:**

Multi-layered, globally distributed web protection architecture combining edge DDoS defense, app-layer filtering, and compliance-ready logging.
