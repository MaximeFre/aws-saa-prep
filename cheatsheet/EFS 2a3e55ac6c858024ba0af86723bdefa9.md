---

## 🧭 **Purpose**

**Amazon Elastic File System (EFS)** provides **scalable, fully managed, shared file storage** that automatically grows and shrinks as files are added or removed.

It’s designed for **multi-instance** access across **multiple Availability Zones**, making it ideal for web apps, analytics, and containerized workloads that need shared storage.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Managed NFS File System** | Provides POSIX-compliant file storage accessible via NFSv4. |
| **Elastic Scalability** | Automatically scales from MBs to petabytes with no provisioning. |
| **Multi-AZ Access** | Accessible concurrently from multiple EC2 instances, containers, or Lambda functions across AZs. |
| **Performance Modes** | `General Purpose` (low latency) and `Max I/O` (higher throughput). |
| **Throughput Modes** | `Bursting` (default, scales with size) and `Provisioned` (fixed, predictable throughput). |
| **Storage Classes** | `EFS Standard` and `EFS Infrequent Access (IA)` for cost optimization. |
| **Lifecycle Management** | Automatically moves files to IA after N days of no access. |
| **Encryption** | Supports KMS for encryption at rest and TLS for data in transit. |
| **Backup Integration** | Supports **AWS Backup** and **EFS-to-EFS replication**. |
| **Access Points** | Simplifies permissions management for multi-user applications. |

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Provide shared storage for web/app servers | Mount **EFS** across multiple EC2 instances |
| Maintain persistent storage for containers | Use **ECS/EKS with EFS integration** |
| Scale file storage automatically without management overhead | Use **EFS** (auto-scales capacity) |
| Store infrequently accessed files cost-effectively | Enable **EFS-IA** lifecycle transition |
| Share files across AZs with high durability | Use **Regional EFS** (multi-AZ) |
| Secure access by user or service | Configure **EFS Access Points + IAM policies** |
| Backup or replicate file systems | Use **EFS Replication** or **AWS Backup** |
| Reduce latency for AZ-specific workloads | Use **One-Zone EFS** (for cost savings) |
| Mount file system inside VPC securely | Use **Mount Targets** within private subnets |
| Replace on-prem NFS servers | Use **EFS** as a cloud-native, managed alternative |

---

## 🔐 **Security Considerations**

- Use **VPC security groups** to control NFS access.
- Encrypt data **at rest** with **KMS** and **in transit** with **TLS**.
- Control access with **POSIX permissions**, **Access Points**, and **IAM policies**.
- Mount targets exist per AZ — isolate them in **private subnets**.
- Use **CloudTrail** and **CloudWatch Logs** for auditing access patterns.

---

## 💲 **Pricing Model**

- Pay for:
    - **Storage used** (GB-month)
    - **IA tier** (cheaper storage, higher retrieval cost)
    - **Provisioned throughput** (if configured)
- **Regional EFS** costs more than **One-Zone EFS**, but offers higher availability.
- Automatically saves cost with **Lifecycle Management** to move unused files to IA.

| Storage Class | Durability | Availability | Cost | Use Case |
| --- | --- | --- | --- | --- |
| **EFS Standard** | 11 9s | Multi-AZ | 💰💰 | Frequently accessed files |
| **EFS Infrequent Access (IA)** | 11 9s | Multi-AZ | 💰 | Infrequent access |
| **EFS One Zone** | 99.9% | Single AZ | 💰 | Lower-cost, non-critical workloads |

## 🔗 **Integration Patterns**

- **EC2:** Mount shared file systems for applications.
- **ECS/EKS:** Use persistent shared volumes for containers.
- **Lambda:** Mount file systems for code needing large libraries or shared data.
- **AWS Backup:** Centralized file system backup.
- **KMS:** Encryption management.
- **CloudWatch:** File system metrics and alerts.

---

## 🧠 **Exam Tips**

✅ EFS = **shared file storage** (multi-instance, multi-AZ).

✅ Automatically scales — **no provisioning** needed.

✅ Use **EFS-IA** + Lifecycle rules for cost optimization.

✅ For **container workloads**, prefer EFS over EBS (shared access).

✅ **EFS vs. EBS:** EFS = multi-instance, EBS = single-instance.

✅ **EFS One Zone** is cheaper but less durable.

✅ Use **Access Points** to enforce application-specific permissions.

✅ Always mount EFS inside a **VPC** using mount targets.

## 🏁 **Real-World Example**

**Scenario:**

A SaaS company runs web applications across multiple EC2 instances behind an Application Load Balancer. Each server must access the same set of media files and logs.

**Solution:**

- Deploy **Amazon EFS** with mount targets in each AZ.
- Attach EFS to all EC2 instances in the Auto Scaling Group.
- Enable **Lifecycle Management** to move cold files to IA.
- Encrypt the file system with **KMS**.
- Use **AWS Backup** for daily snapshots.

**Outcome:**

A scalable, resilient, and cost-efficient shared storage layer with automatic scaling and zero administrative overhead.
