# **AWS Key Management Service (KMS) – Study Sheet**

*(Centralized key management for encryption and access control across AWS)*

**Exam Domains:**

- Design Secure Architectures
- Design Cost-Optimized Architectures

---

## 🧭 **Purpose**

**AWS Key Management Service (KMS)** is a **managed service for creating, controlling, and auditing encryption keys** used to protect data across AWS.

It provides **centralized key management**, **fine-grained access control**, and **integration with most AWS services** for encryption at rest and in transit.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Customer Master Keys (CMKs)** | Core encryption keys managed by KMS (now called *KMS Keys*). |
| **AWS-Managed Keys (aws/service-name)** | Automatically created and managed by AWS for each service. |
| **Customer-Managed Keys (CMKs)** | Created, rotated, and managed by you; supports policies and grants. |
| **Symmetric Keys** | Used for most encryption operations (AES-256). |
| **Asymmetric Keys (RSA/ECC)** | Used for digital signing and encryption outside AWS. |
| **Key Policies** | Define who can use or manage a key; primary access control mechanism. |
| **Grants** | Temporary delegated permissions to use a CMK for specific operations. |
| **Automatic Key Rotation** | Supported every 1 year for CMKs (optional). |
| **Envelope Encryption** | Encrypts data keys (DEKs) with a CMK for scalable performance. |
| **Integration with AWS Services** | Works natively with S3, EBS, RDS, DynamoDB, Lambda, Secrets Manager, etc. |
| **Audit Logging** | Every API call logged in **AWS CloudTrail** for compliance. |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Encrypt data at rest in S3, EBS, or RDS | Use **SSE-KMS** |
| Encrypt Lambda environment variables | Use **KMS-managed CMK** |
| Enable server-side encryption for S3 | Choose **SSE-KMS** instead of SSE-S3 for key visibility |
| Grant another AWS account temporary key usage | Create a **KMS Grant** |
| Rotate encryption keys automatically | Enable **Automatic Key Rotation** |
| Use application-level encryption | Call **Encrypt/Decrypt APIs** directly from KMS |
| Sign and verify digital documents | Use **Asymmetric CMK (RSA/ECC)** |
| Manage encryption for all accounts centrally | Use **AWS Organizations + KMS multi-account key policies** |
| Encrypt cross-Region backups | Replicate CMKs using **multi-Region KMS keys** |
| Audit all encryption activity | Use **CloudTrail logs** for KMS API events |

---

## 🔐 **Security Considerations**

- **KMS keys never leave AWS** — all encryption operations happen inside the service.
- **Key Policies** are mandatory for granting access (IAM policies alone aren’t enough).
- Use **Grants** for short-term key sharing between services.
- Always apply **least privilege** in both key and IAM policies.
- Enable **Automatic Key Rotation** for customer-managed CMKs.
- Log and audit all KMS events via **CloudTrail**.
- Use **multi-Region keys** for DR and cross-Region backups.
- Encrypt sensitive config and credentials in **Secrets Manager** or **SSM Parameter Store**.
- Integrate **VPC Endpoints** to keep encryption calls inside the AWS network.

---

## 💲 **Pricing Model**

- **Free tier:** 20,000 requests/month.
- **Pay for:**
    - CMK creation ($1/month per CMK)
    - API requests (Encrypt, Decrypt, GenerateDataKey, etc.)
    - Cross-account and multi-Region operations.
- AWS-managed keys incur **no monthly charge** (only request costs).

| Key Type | Management | Rotation | Cost |
| --- | --- | --- | --- |
| **AWS-Managed CMK** | Fully managed by AWS | Automatic | Free (per-use billing) |
| **Customer-Managed CMK** | Created and managed by you | Optional (1-year) | $1/month + requests |
| **Multi-Region CMK** | Replicable across Regions | Manual | Same as CMK + replication cost |

## 🔗 **Integration Patterns**

- **S3, EBS, RDS, DynamoDB:** Encrypt data with SSE-KMS.
- **Lambda / ECS:** Encrypt environment variables or secrets.
- **Secrets Manager / SSM Parameter Store:** Use CMKs to encrypt sensitive values.
- **CloudTrail:** Audit all key usage events.
- **AWS Organizations:** Centralized key policy management across accounts.
- **CodeBuild / CodePipeline:** Encrypt build artifacts and environment data.

## 🧠 **Exam Tips**

✅ **KMS = centralized encryption and key control service.**

✅ **Customer-Managed Keys (CMKs)** give full control and audit visibility.

✅ **Envelope encryption** improves performance by reusing data keys.

✅ **Automatic key rotation** = every 1 year for CMKs only (not AWS-managed keys).

✅ **KMS API calls are logged** in **CloudTrail** — critical for compliance.

✅ **Grants** = short-term, fine-grained delegation of key usage.

✅ **Multi-Region keys** simplify encrypted DR designs.

✅ **Key policies override IAM policies** — both must allow access.

✅ For **cross-account encryption**, both accounts’ key policies must permit use.

✅ Most AWS services integrate natively with KMS (S3, EBS, RDS, Lambda, etc.).

---

## 🏁 **Real-World Example**

**Scenario:**

A healthcare SaaS provider must encrypt patient data stored in S3, RDS, and DynamoDB, enforce key rotation, and meet compliance for key usage tracking.

**Solution:**

- Create **Customer-Managed CMKs** in KMS with automatic rotation.
- Apply **SSE-KMS** to all data stores (S3, EBS, RDS).
- Grant specific IAM roles access via key policies and grants.
- Log key usage with **CloudTrail** for audit compliance.
- Replicate CMKs using **multi-Region keys** for DR readiness.

**Outcome:**

A secure, compliant encryption framework with centralized control, detailed auditing, and automated key lifecycle management.
