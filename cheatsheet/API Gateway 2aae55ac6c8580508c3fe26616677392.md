# **Amazon API Gateway – Study Sheet**

*(Managed API service for REST, HTTP, and WebSocket APIs)*

**Exam Domains:**

- Design High-Performing Architectures
- Design Secure Architectures
- Design Cost-Optimized Architectures

---

## 🧭 **Purpose**

**Amazon API Gateway** is a fully managed service for **creating, securing, and scaling APIs**.

It supports 3 types of APIs:

### 🔵 **REST APIs**

Full-featured, advanced integrations, request validation, usage plans, caching.

(Older but more powerful — still heavily tested.)

### 🟢 **HTTP APIs**

Lower cost, faster, simpler, built for Lambda, ALB, and service → service communication.

### 🟣 **WebSocket APIs**

Bidirectional, persistent real-time communication (chat apps, dashboards).

---

## ⚙️ **Key Features**

| Capability | REST API | HTTP API | WebSocket API |
| --- | --- | --- | --- |
| Lambda proxy | Yes | Yes | Yes |
| AWS service integrations | Yes | Yes (limited) | No |
| Caching | Yes | No | No |
| Request validation | Yes | No | No |
| Custom auth (Lambda Authorizer) | Yes | Yes (JWT or Lambda) | Yes |
| JWT / OIDC auth | No | Yes | No |
| Resource policies | Yes | Yes | Yes |
| WAF integration | Yes | Yes | Yes |
| Pricing | Expensive | Cheaper | Connection-based |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Serverless REST API with request validation | **REST API + Lambda** |
| Low-cost HTTPS endpoint for microservices | **HTTP API** |
| Real-time chat, dashboards, IoT messages | **WebSocket API** |
| On-prem/VPC service behind an API | API Gateway → **VPC Link → NLB** |
| Rate limiting and API keys | **Usage plans (REST only)** |
| Protect APIs with Cognito JWT tokens | **HTTP API with JWT auth** |
| Cached API responses for performance | **REST API + Caching** |
| Offloading auth logic | **Lambda Authorizer** |
| Multi-account/multi-Region API access | **Resource Policies** |

## 🔐 **Security Considerations**

- **IAM authorization** for internal APIs
- **Cognito User Pools** for user-based auth
- **Lambda Authorizers** for custom auth flows
- **JWT Authorizers** (HTTP APIs only)
- **Resource Policies** to:
    - allow access from specific VPCs
    - deny public requests
    - limit access by IP/ranges
- **WAF** for injection/DDOS protection
- **TLS enforced** for all endpoints

---

## 💲 **Pricing Model**

### REST APIs

- Per million requests → **highest cost**
- Optional caching layer (charged per hour)
- Data transfer charges

### HTTP APIs

- ~70% cheaper than REST APIs
- No caching
- Great for Lambda, private services, auth pipelines

### WebSocket APIs

- Charged per **connection-minute** + per message

💡 **Exam Tip:**

If the question mentions **cost reduction**, the answer is *almost always* **HTTP API** unless you need features only available in REST.

---

## 🔗 **Integration Patterns**

- **Lambda Proxy Integration** → most common
- **VPC Link → NLB** → access private services
- **SQS/SNS through Lambda**
- **Direct Service Integrations**:
    - SQS
    - Step Functions
    - EventBridge
- **CloudFront** for edge-optimized APIs
- **Cognito → API Gateway** for user auth

---

## 🧠 **Exam Tips**

- **REST API = fully featured**
- **HTTP API = cheaper / faster / simpler**
- **WebSocket = real-time**
- **Caching only in REST API**
- **Private API** access requires:
    - Resource policies
    - VPC Endpoints
- **Usage Plans & API Keys → REST only**
- **JWT Auth** → HTTP APIs only
- **VPC Link** required to expose private services (use **NLB**, not ALB).
- **Throttling** at:
    - Account level
    - Stage level
    - Usage plan level (REST only)

## 🏁 **Real-World Example**

**Scenario:**

A mobile app needs a cost-efficient serverless backend for login, real-time notifications, and business logic.

**Solution:**

- **HTTP API** for all business logic (low cost, JWT auth)
- **Lambda backend** for compute
- **Cognito** for authentication
- **WebSocket API** for real-time notifications

**Outcome:**

Highly scalable, low-cost serverless architecture that supports both API calls and real-time messaging.
