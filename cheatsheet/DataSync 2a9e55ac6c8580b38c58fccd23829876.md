---

## 🧭 **Purpose**

**AWS DataSync** simplifies and speeds up **online data migration** by automating transfers between **on-premises storage systems** and **AWS Storage services** such as **S3, EFS, FSx**.

It’s built for **large-scale or recurring data movement** — ideal when Snow Family is too slow and manual sync tools (rsync, scp) are inefficient.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **High-speed data transfer** | 10× faster than traditional tools using parallel network channels. |
| **Fully managed service** | No need to manage servers or scripts; AWS handles scaling and security. |
| **Supports multiple endpoints** | On-prem NAS (NFS/SMB), Amazon S3, EFS, and FSx for Windows/Lustre. |
| **Incremental transfers** | Only changes (delta sync) are moved after initial transfer. |
| **Encryption & integrity** | Data encrypted in transit (TLS) and at rest (KMS); integrity checks enabled. |
| **Task scheduling & monitoring** | Automate recurring transfers and view CloudWatch metrics. |
| **Bandwidth control** | Throttle transfer rates to avoid saturating links. |
| **Hybrid or Cloud-to-Cloud moves** | Supports S3 ⇆ EFS, EFS ⇆ FSx, etc. |
| **Agent-based model** | Install DataSync Agent VM on on-prem VMware/Hyper-V to initiate transfer. |
| **POSIX metadata preservation** | Maintains ownership, timestamps, and permissions. |

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Migrate on-prem NAS to S3 for archival | Use **DataSync Agent** (NFS source) → S3 bucket destination |
| Sync file shares to EFS with metadata intact | DataSync task (EFS target, preserve permissions) |
| Hybrid data sync between two AWS Regions | Use **EFS ⇆ EFS** via DataSync |
| Replicate Windows file server data to FSx | Use **SMB source → FSx for Windows** |
| Recurring backup of on-prem files to AWS | **Schedule DataSync tasks** to run daily/weekly |
| Accelerate one-time 5 TB migration over VPN | Deploy **DataSync Agent** inside VPC, enable TLS |
| Limit transfer bandwidth on corporate link | Set **Bandwidth limit** on task configuration |
| Transfer data securely without VPN | Use **Direct Connect + DataSync over private VIF** |

## 🔐 **Security Considerations**

- Agent initiates outbound traffic to AWS (over HTTPS 443) — no inbound ports open.
- Encrypt data **in transit (TLS)** and **at rest (KMS)**.
- Run agents in **private subnets** for isolation.
- Control access via **IAM roles** (`datasync:*`, `s3:*`, `efs:*`).
- Monitor tasks in **CloudWatch Logs + CloudTrail**.
- Delete tasks and endpoints after migration for compliance.

## 🔗 **Integration Patterns**

- **S3 + Glacier:** DataSync for transfer + lifecycle policies for archival.
- **EFS → FSx:** Modernize file systems without manual copy.
- **CloudWatch:** Track task duration and throughput.
- **CloudTrail:** Log task creation and execution API calls.
- **Systems Manager:** Automate recurring transfer jobs.
- **Direct Connect:** Private high-bandwidth transfers.

## 🧠 **Exam Tips**

✅ **DataSync = automated online data transfer** (on-prem ↔ AWS).

✅ Agent required for on-prem sources (NFS or SMB).

✅ Supports **S3, EFS, FSx** as targets.

✅ Only **differential data is copied** after initial load.

✅ Can run **recurring syncs** for hybrid environments.

✅ Encrypted with **TLS + KMS**.

✅ Compare to:

- **Snowball** → offline bulk transfer.
- **Transfer Family** → SFTP/FTP workloads.
    
    ✅ Exam focus = difference between DataSync (automated, online) vs Snow Family (offline).

## 🏁 **Real-World Example**

**Scenario:**

A biotech company must move 50 TB of data from its on-prem NAS to Amazon S3 for long-term storage and later analytics with Athena.

**Solution:**

- Deploy **DataSync Agent** on VMware.
- Create **NFS source location** and **S3 target bucket**.
- Run **initial full transfer**, then enable **incremental sync**.
- Monitor progress in **CloudWatch** and validate integrity after each run.

**Outcome:**

Automated, secure, and 10× faster transfer than rsync, fully encrypted and tracked via CloudTrail.
