# **Amazon Cognito – Study Sheet**

*(User authentication, authorization, and identity federation service)*

**Exam Domains:**

- Design Secure Architectures
- Design Resilient Architectures

---

## 🧭 **Purpose**

**Amazon Cognito** provides **user authentication and access control** for web and mobile apps.

It supports:

- **User Pools** for **sign-up/sign-in** and user management, and
- **Identity Pools** for granting **temporary AWS credentials** to access AWS resources.
    
    Cognito can also **federate identities** from social, SAML, or OpenID Connect providers.
    

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **User Pools** | Managed user directory for authentication (signup, login, password recovery). |
| **Identity Pools (Federated Identities)** | Provide AWS credentials to users (via STS) to access AWS resources. |
| **Hosted UI** | Ready-made, customizable sign-in page with OAuth2 support. |
| **Federation** | Integrate with **Google, Facebook, Apple, SAML, or OIDC IdPs**. |
| **MFA & Adaptive Authentication** | Enforce MFA or challenge suspicious logins automatically. |
| **Custom Authentication Flows** | Use Lambda triggers (Pre-Signup, Post-Authentication, etc.) for logic customization. |
| **Access Tokens (JWT)** | Used for app authentication and authorization (ID, Access, Refresh tokens). |
| **Fine-Grained Access Control** | Assign IAM roles dynamically via Identity Pool role mapping. |
| **Integration with API Gateway** | Authorize API calls using **Cognito User Pool Authorizer**. |
| **Device Tracking** | Recognizes user devices for enhanced security. |

## 🔐 **Security Considerations**

- Store user credentials securely — Cognito handles hashing and salting.
- Use **MFA** for sensitive accounts.
- Rotate **app client secrets** periodically.
- For AWS resource access, Cognito issues **temporary STS credentials** (never permanent).
- Use **least privilege IAM roles** for Identity Pool mappings.
- Log all authentication and federation activity with **CloudTrail**.
- Integrate **AWS WAF** or **Shield** for API protection when combined with API Gateway.

## 💲 **Pricing Model**

- **User Pools:** Free for 50,000 monthly active users (MAUs); then pay per MAU.
- **Identity Pools:** Pay only for AWS resources accessed with temporary credentials.
- **MFA / Federation:** Included; SMS MFA incurs Amazon SNS charges.

| Component | Free Tier | Cost Beyond Free Tier |
| --- | --- | --- |
| **User Pool (Authentication)** | 50k MAUs | ~$0.0055 per MAU |
| **Federated Identities (STS)** | 50k MAUs | Same pricing |
| **SMS MFA** | N/A | Pay per SMS via SNS |

## 🔗 **Integration Patterns**

- **API Gateway:** Use Cognito as an authorizer for REST/HTTP APIs.
- **Lambda Triggers:** Run code at various authentication lifecycle stages (e.g., PreSignUp).
- **CloudFront / AppSync:** Secure access to web/mobile content.
- **AWS Amplify:** Simplified integration with frontend apps.
- **STS / IAM:** Identity Pool roles for AWS resource access.
- **CloudTrail:** Log sign-in and federation events for audit.

## 🧠 **Exam Tips**

✅ **User Pool = authentication (who the user is).**

✅ **Identity Pool = authorization (what the user can access).**

✅ Cognito issues **JWT tokens (ID, Access, Refresh)** for federated sessions.

✅ **Federation** allows use of external IdPs (Google, Facebook, SAML, OIDC).

✅ **User Pools integrate with API Gateway** for secure access.

✅ **Identity Pools use IAM roles** for AWS resource permissions.

✅ Use **MFA** and **adaptive authentication** for compliance.

✅ For enterprise auth → **Cognito + SAML federation**.

✅ **Cognito is regional**, not global.

✅ Use **Lambda triggers** to customize authentication flows (PreSignup, PostAuth, etc.).

## 🏁 **Real-World Example**

**Scenario:**

A startup builds a mobile application that lets users log in with Google or Facebook and upload images to an S3 bucket — but only their own.

**Solution:**

- Configure a **Cognito User Pool** with **social federation (Google/Facebook)**.
- Use an **Identity Pool** to map users to **IAM roles** via **STS**.
- Grant each user an IAM policy allowing `s3:PutObject` to a specific key prefix (`userID/*`).
- Protect APIs with **API Gateway + Cognito Authorizer**.
- Enable **MFA** and log access with **CloudTrail**.

**Outcome:**

Secure, scalable authentication and authorization without managing credentials, fully integrated with AWS services.
