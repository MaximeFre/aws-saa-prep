## 🧭 **Purpose**

**AWS Lambda** lets you run code **without provisioning or managing servers**. It automatically scales and executes your functions in response to events, charging you only for compute time used.

It’s the foundation of **serverless**, **event-driven** architecture in AWS.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Event-Driven Execution** | Runs code in response to triggers (S3, API Gateway, EventBridge, DynamoDB Streams, etc.). |
| **Automatic Scaling** | Scales concurrency automatically based on request volume. |
| **Flexible Language Support** | Node.js, Python, Java, Go, .NET, Ruby, custom runtimes. |
| **Ephemeral Compute** | Stateless execution environment (max 15 min runtime). |
| **Environment Variables** | Store configuration outside code. |
| **Concurrency Controls** | Limit or reserve function concurrency for predictable throughput. |
| **Versions & Aliases** | Manage function versions and implement blue/green or canary deployments. |
| **VPC Integration** | Access private subnets and RDS via Elastic Network Interfaces (ENIs). |
| **Lambda Layers** | Reuse common libraries and dependencies across functions. |
| **Provisioned Concurrency** | Pre-initializes execution environments to reduce cold starts. |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Process uploaded images or files in S3 | Trigger **Lambda** via **S3 Put event** |
| Build serverless API backends | Integrate **API Gateway + Lambda** |
| Stream data from IoT or Kinesis for processing | Use **Lambda triggers** on **Kinesis Streams** |
| Automate responses to infrastructure events | Use **CloudWatch Events (EventBridge)** to invoke Lambda |
| Connect Lambda to private RDS | Enable **VPC access** (create ENIs in subnets) |
| Reduce startup latency for critical functions | Enable **Provisioned Concurrency** |
| Manage environment configs securely | Use **AWS Secrets Manager or SSM Parameter Store** |
| Implement serverless ETL or data transformations | Combine **Lambda + S3 + Glue/Athena** |
| Schedule periodic tasks | Use **EventBridge (CloudWatch Schedule rule)** |
| Enforce real-time security remediation | Trigger Lambda from **GuardDuty** or **Config Rules** |

## 🔐 **Security Considerations**

- Each function assumes an **IAM execution role** (least-privilege policy).
- Encrypt environment variables with **KMS**.
- Restrict network access with **VPC Security Groups** and **NACLs**.
- Use **CloudTrail** and **CloudWatch Logs** for auditing.
- Manage secrets via **Secrets Manager** or **Parameter Store**, not plain env vars.

---

## 💲 **Pricing Model**

- **Request charges:** $0.20 per million requests.
- **Duration charges:** Based on GB-seconds (allocated memory × execution time).
- **Provisioned Concurrency:** Additional cost for pre-warmed instances.
- No charge when function is idle.

## 🔗 **Integration Patterns**

- **S3, DynamoDB, Kinesis, SNS, SQS, EventBridge:** as event sources.
- **API Gateway:** serverless REST or HTTP APIs.
- **Step Functions:** orchestrate complex workflows.
- **CloudWatch:** metrics & logs.
- **X-Ray:** trace function performance.
- **EFS:** attach persistent file systems for shared storage use cases.

---

## 🧠 **Exam Tips**

✅ Lambda runs code without managing servers — pay only for runtime.

✅ Functions are **stateless**; use S3/DynamoDB for persistence.

✅ Max execution = **15 minutes**.

✅ Cold starts occur when new execution environments are created — use **Provisioned Concurrency** to reduce them.

✅ Integrate with **API Gateway** for HTTP invocation or **S3/Kinesis** for event invocation.

✅ Each function has a **default timeout of 3 seconds** – tune for workload.

✅ Keep deployment package < 250 MB (zip) or use **Lambda Layers**.

✅ Use **CloudWatch Logs** for troubleshooting invocations and failures.

## 🏁 **Real-World Example**

**Scenario:**

A company wants to automatically generate thumbnails every time an image is uploaded to S3.

**Solution:**

- Configure S3 bucket “upload” with an **Object Created** event triggering a Lambda function.
- Lambda reads the image from S3, creates a thumbnail, and stores it in an “images-resized” bucket.
- Logs and metrics are sent to **CloudWatch** for monitoring.

**Outcome:**

Fully serverless, auto-scaling image-processing pipeline with zero infrastructure management and pay-per-use pricing.
