---

## 🧭 **Purpose**

**Amazon Virtual Private Cloud (VPC)** lets you **provision a logically isolated section** of the AWS Cloud where you can launch and manage resources (like EC2, RDS, and Lambda) in a secure, customizable network.

You control IP addressing, subnets, routing, internet access, and security boundaries.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Subnets** | Divide your VPC into public and private networks (each in a single AZ). |
| **Route Tables** | Define how traffic flows between subnets, gateways, and endpoints. |
| **Internet Gateway (IGW)** | Enables public internet access for instances in public subnets. |
| **NAT Gateway / NAT Instance** | Allows outbound internet traffic from private subnets while blocking inbound access. |
| **VPC Peering** | Private connectivity between two VPCs (same or different accounts/Regions). |
| **Transit Gateway** | Centralized hub for connecting multiple VPCs and on-premises networks. |
| **VPC Endpoints (Gateway / Interface)** | Private access to AWS services without using the internet. |
| **Network ACLs (NACLs)** | Stateless subnet-level firewalls (rules evaluated in order). |
| **Security Groups (SGs)** | Stateful instance-level firewalls controlling inbound/outbound traffic. |
| **Elastic IPs** | Static public IP addresses that can be remapped between instances. |
| **DHCP Options Sets** | Configure DNS resolution within the VPC. |
| **Flow Logs** | Capture IP traffic metadata for analysis and troubleshooting. |
| **PrivateLink** | Secure private connectivity to AWS services and third-party SaaS applications. |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Isolate workloads and control IP ranges | Create a **custom VPC** with CIDR block (e.g., 10.0.0.0/16) |
| Allow EC2 instances to access the internet | Place them in a **public subnet** with **IGW** |
| Enable private instances to access internet updates | Use **NAT Gateway** in a public subnet |
| Secure communication between VPCs | Use **VPC Peering** (for few VPCs) or **Transit Gateway** (for many) |
| Access AWS services without public IPs | Use **VPC Endpoints** (Gateway for S3/DynamoDB, Interface for others) |
| Enforce subnet-level security | Configure **NACLs** (stateless, ordered rules) |
| Enforce instance-level security | Use **Security Groups** (stateful, default deny inbound) |
| Capture network traffic for troubleshooting | Enable **VPC Flow Logs** to S3 or CloudWatch |
| Connect on-premises network to AWS | Use **Site-to-Site VPN** or **Direct Connect Gateway** |
| Expose internal services securely to partners | Use **AWS PrivateLink** |
| Centralize hybrid connectivity | Connect via **Transit Gateway** |

## 🔐 **Security Considerations**

- **Security Groups** are **stateful** — return traffic automatically allowed.
- **NACLs** are **stateless** — must define both inbound and outbound rules.
- Use **least privilege** in SG/NACL design.
- Keep **private subnets** without IGW for internal workloads.
- Use **VPC Endpoints** for secure private service access.
- Apply **Flow Logs** to detect suspicious network traffic.
- Control inter-VPC routing with **Transit Gateway route tables**.
- Always enable **encryption in transit** (TLS/IPsec) for VPN and DX.

---

## 💲 **Pricing Model**

- **No charge** for VPC creation or subnets.
- **Costs apply** for:
    - **NAT Gateways** (per hour + per GB processed)
    - **VPC Endpoints** (per hour + data processed)
    - **Transit Gateway attachments** and data processing
    - **Traffic between AZs or Regions**
- **Security Groups and NACLs** are free.

---

## 🔗 **Integration Patterns**

- **EC2, RDS, Lambda, ECS/EKS:** Run within VPC subnets.
- **VPN / Direct Connect:** Hybrid connectivity.
- **CloudWatch + Flow Logs:** Monitoring and auditing.
- **PrivateLink:** Access SaaS or AWS services privately.
- **Transit Gateway:** Multi-VPC and hybrid network hub.
- **IAM:** Manage who can modify VPC configuration.

---

## 🧠 **Exam Tips**

✅ **VPC = your isolated AWS network.**

✅ **Security Groups = stateful**, **NACLs = stateless.**

✅ **IGW = inbound/outbound internet**, **NAT Gateway = outbound only.**

✅ **VPC Peering is non-transitive** — Transit Gateway solves multi-VPC hub needs.

✅ **Endpoints** = private AWS service access (no public internet).

✅ **Flow Logs** do **not capture DNS or metadata traffic**.

✅ Keep **management and application subnets separate** for security.

✅ For **hybrid connectivity**, use **VPN or Direct Connect Gateway**.

✅ **CIDR blocks cannot overlap** when peering or attaching to Transit Gateway.

## 🏁 **Real-World Example**

**Scenario:**

A retail company wants to host web servers that serve customers publicly and connect privately to internal application and database servers.

**Solution:**

- Create a **custom VPC (10.0.0.0/16)** with **public** and **private subnets** in each AZ.
- Attach an **Internet Gateway** for web servers in public subnets.
- Deploy **NAT Gateway** in the public subnet for private instances.
- Secure instances using **Security Groups** and **NACLs**.
- Enable **Flow Logs** for auditing traffic.
- Use **VPC Endpoints** for private S3 and DynamoDB access.

**Outcome:**

A secure, multi-tier, high-availability network design that isolates workloads and minimizes exposure to the public internet.
