*(Serverless interactive query service to analyze data in Amazon S3 using SQL)*

**Exam Domains:**

- Design Cost-Optimized Architectures

---

## 🧭 **Purpose**

**Amazon Athena** is a **serverless query service** that lets you run **SQL queries directly on data stored in Amazon S3**.

It’s ideal for **ad hoc analytics**, **log analysis**, and **data lake exploration**—with no need to manage infrastructure or ETL pipelines.

It uses **Presto (Trino)** under the hood and integrates with the **AWS Glue Data Catalog** for schema management.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Serverless SQL Engine** | Query data in S3 directly—no servers to provision. |
| **Pay-per-query model** | Pay only for the amount of data scanned (per TB). |
| **Multiple Formats Supported** | CSV, JSON, ORC, Parquet, Avro, and more. |
| **Glue Data Catalog Integration** | Store and reuse schemas across multiple services. |
| **Partitioning** | Query only subsets of data to reduce cost and improve performance. |
| **Federated Queries** | Query across S3, RDS, DynamoDB, Redshift, or on-prem sources via connectors. |
| **Result Storage** | Query results automatically written to S3. |
| **Encryption Support** | Encrypt results and queries with KMS. |
| **Integration with QuickSight** | Visualize Athena query results directly. |

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Ad-hoc analytics on data lake stored in S3 | Use **Athena with Glue Data Catalog** |
| Query structured and semi-structured logs (CloudFront, ELB) | Create **external tables** in Athena with proper SerDe |
| Reduce query cost and speed up performance | Convert data to **Parquet + Partition by key** |
| Build dashboards over raw S3 data | Connect **QuickSight → Athena** |
| Query data in multiple AWS accounts | Use **Cross-account Glue Catalog** |
| Query data stored in RDS or DynamoDB | Use **Federated Query Connector** |
| Secure data access | Encrypt results with **KMS** and enforce **IAM permissions** |
| Automate scheduled queries | Use **Athena + EventBridge/Lambda** to run reports |
| Build a cost-efficient data lake | Combine **S3 + Glue + Athena** |

## 🔐 **Security Considerations**

- All data stays in **S3** — Athena never moves it.
- **IAM policies** control access to S3 buckets and Athena queries.
- **KMS encryption** for both query results and data at rest.
- **VPC Endpoints** supported for private S3 access.
- Integration with **CloudTrail** for query logging.
- **Access logs** can be stored in S3 for audit.

---

## 💲 **Pricing Model**

| Component | Cost | Notes |
| --- | --- | --- |
| **Queries** | $5 per TB scanned | Reduce cost with compression & columnar formats |
| **Storage** | S3 rates apply | Query results + table metadata |
| **Glue Data Catalog** | Separate pricing | ~$1 per 100,000 requests |
| **Federated Queries** | Pay for connector execution | Based on data scanned remotely |

💡 **Tip:**

Convert large CSVs to **Parquet** and **partition by date** to cut query cost by 90%.

## 🔗 **Integration Patterns**

- **AWS Glue:** Schema and metadata management.
- **Amazon QuickSight:** Visualization and dashboards.
- **S3:** Raw and transformed data storage.
- **EventBridge / Lambda:** Automate periodic reports.
- **Lake Formation:** Fine-grained permissions for data lakes.
- **CloudTrail:** Log Athena query usage for compliance.

## 🧠 **Exam Tips**

✅ **Athena = serverless SQL on S3.**

✅ Requires **Glue Data Catalog** for table definitions.

✅ **Pay per TB scanned** — compress + partition to save cost.

✅ **Common formats:** Parquet (columnar) → fastest, cheapest.

✅ **No infrastructure** to manage or scale manually.

✅ Federated queries supported (e.g., RDS, DynamoDB).

✅ **Output results to S3** (can be encrypted with KMS).

✅ **IAM permissions** control query and data access.

✅ Compare to **Redshift Spectrum** (similar concept but tied to Redshift).

✅ Excellent for **ad-hoc queries**, **log analytics**, and **data lake exploration**.

## 🏁 **Real-World Example**

**Scenario:**

A SaaS company stores 50 TB of application logs in Amazon S3 (partitioned by date) and wants to analyze user activity trends weekly without maintaining an analytics cluster.

**Solution:**

- Define table schema in **AWS Glue Data Catalog**.
- Run **Athena queries** directly on S3 using **Parquet format**.
- Store results in S3 and visualize in **QuickSight**.
- Automate weekly reports using **EventBridge + Lambda**.

**Outcome:**

Low-cost, zero-maintenance analytics pipeline leveraging S3 as a data lake, Athena for query, and QuickSight for visualization.
