# 🟥 **FSx for Windows File Server**

*(Fully managed Windows file system with SMB + Active Directory)*

## 🧭 Purpose

Designed for **Windows workloads**, providing SMB shares with **native Windows features**.

---

## ⚙️ Key Features

- SMB protocol
- Fully integrated with **AWS Managed AD** or **Self-managed AD**
- **NTFS permissions**, ACLs, user quotas
- Distributed file system (DFS)
- Highly available (Multi-AZ)
- Supports **MS SQL Server**, home directories, Windows apps

---

## 🏗️ Common Use Cases

| Scenario | FSx Windows? |
| --- | --- |
| Windows apps needing SMB | ✅ |
| Lift-and-shift Windows servers | ✅ |
| AD-integrated file share | ✅ |
| Home directories for end users | ✅ |
| Linux/POSIX workloads | ❌ |

---

## 🧠 Exam Tips

- **Only FSx that supports SMB**.
- AD integration is mandatory.
- Multi-AZ option for HA.

# 🟨 **FSx for Lustre**

*(High-performance parallel file system for HPC, ML, analytics)*

## 🧭 Purpose

Built for **high-throughput, low-latency, parallel workloads**.

Commonly paired with:

- **EKS**
- **ECS**
- **EC2 clusters**
- **SageMaker**
- **HPC clusters**

---

## ⚙️ Key Features

- Extremely high throughput & IOPS
- Sub-millisecond latencies
- POSIX-compliant
- Native **S3 integration** (“import/export paths”)
- Ideal for **GPU/ML training**, analytics pipelines

---

## 🏗️ Common Use Cases

| Scenario | Recommended? |
| --- | --- |
| Machine learning training | ✅ |
| HPC workloads | ✅ |
| Video processing / rendering | ✅ |
| High-throughput workloads | ✅ |
| General-purpose storage | ❌ |

---

## 🧠 Exam Tips

- If the question says **“high throughput”**, **“parallel file system”**, or **“ML training on S3 datasets”** → choose **FSx for Lustre**.
- Automatically syncs files with **S3**.

# 🟦 **FSx for NetApp ONTAP**

*(Enterprise-grade NAS: NFS, SMB, multi-protocol, snapshots, clones)*

## 🧭 Purpose

Enterprise NAS with **multi-protocol access**:

- **NFS**
- **SMB**
- **iSCSI**

Perfect for lift-and-shift of enterprise storage systems.

---

## ⚙️ Key Features

- NFS, SMB, iSCSI
- Multi-protocol file access
- Snapshots, cloning, deduplication
- Multi-AZ support
- Tiering to S3 via FabricPool
- High IOPS for transactional workloads

---

## 🏗️ Common Use Cases

| Scenario | FSx ONTAP? |
| --- | --- |
| Enterprise NAS migration | ✅ |
| Applications requiring NFS + SMB | ✅ |
| VMware, Kubernetes, Windows + Linux mix | ✅ |
| Storage efficiency features (snapshot, clone) | ✅ |
| Extreme HPC performance | ❌ (use Lustre) |

---

## 🧠 Exam Tips

- If the question mentions **multi-protocol** → ONTAP.
- If it mentions **iSCSI** → ONTAP (only FSx that supports it).
- If it mentions **storage efficiency (snapshots, clones)** → ONTAP.

# 🟩 **FSx for OpenZFS**

*(Low-latency NFS for Linux workloads and ZFS-based systems)*

## 🧭 Purpose

A managed ZFS file system with:

- Very low latency
- High IOPS
- **NFS protocol**
- Ideal for Linux workloads and single-node file servers

---

## ⚙️ Key Features

- NFSv3, NFSv4
- ZFS snapshots, clones
- Single-AZ performance focus
- Lower cost than ONTAP
- Fast metadata operations

---

## 🏗️ Common Use Cases

| Scenario | Recommended? |
| --- | --- |
| ZFS-based workloads | ✅ |
| High-performance Linux file systems | ✅ |
| Build farms, DevOps tooling | ✅ |
| Multi-protocol (SMB) | ❌ (use ONTAP or Windows FSx) |

---

## 🧠 Exam Tips

- **FSx OpenZFS = high-performance NFS**.
- If the question says “ZFS,” “Linux file server,” or “low-latency POSIX” → choose **OpenZFS**.

# 🏁 Real-World Example

**Scenario:**

A research team needs to train ML models using 500 TB of data stored in S3, with extremely high read throughput.

**Solution:**

- Use **FSx for Lustre** with S3 integration.
- Connect from EC2 GPU nodes or EKS.

High-throughput, low-latency file system optimized for ML training.
