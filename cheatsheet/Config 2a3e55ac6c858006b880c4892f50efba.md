---

## 🧭 **Purpose**

**AWS Config** provides **continuous monitoring and recording of AWS resource configurations**.

It helps you **audit changes**, **enforce compliance**, and **analyze resource relationships** over time.

You can define **rules** to automatically detect drift from desired configurations and trigger **remediation actions**.

---

## ⚙️ **Key Features**

| Feature | Description |
| --- | --- |
| **Configuration Recorder** | Tracks changes to resource configurations and relationships. |
| **Config Rules** | Define compliance checks (AWS-managed or custom). |
| **Managed Rules Library** | 100+ prebuilt rules (e.g., “S3 buckets must be encrypted”). |
| **Custom Rules** | Use **AWS Lambda** to define custom compliance logic. |
| **Remediation Actions** | Automatically fix noncompliant resources (e.g., enable encryption). |
| **Configuration History** | View historical configuration changes for any resource. |
| **Configuration Snapshot** | Point-in-time snapshot of resource states. |
| **Aggregators** | Combine Config data across multiple accounts and Regions. |
| **Resource Relationship Graph** | Visualize dependencies (e.g., which security group is attached to which instance). |
| **Integration with Security Hub** | Shares compliance findings. |

---

## 🏗️ **Common Exam Use Cases**

| Scenario | Recommended Solution |
| --- | --- |
| Track all configuration changes in an AWS account | Enable **AWS Config Recorder** |
| Detect unencrypted S3 buckets | Use **AWS Managed Rule – s3-bucket-server-side-encryption-enabled** |
| Automatically remediate noncompliant resources | Create **Remediation Action** with **Systems Manager Automation Document** |
| Maintain compliance across multiple accounts | Use **Aggregators + AWS Organizations** |
| Store configuration history securely | Deliver data to **S3 (KMS-encrypted)** |
| Alert when public access is enabled on Security Groups | Use **Managed Rule – restricted-ssh** |
| Visualize resource relationships | Use **Config Resource Graph** |
| Integrate compliance data with Security Hub | Enable **Config + Security Hub integration** |
| Audit IAM policy changes | Use Config to track **IAM Role and Policy resources** |
| Support compliance frameworks (CIS, PCI DSS) | Enable **AWS Config Rules + Conformance Packs** |

## 🔐 **Security Considerations**

- All configuration and compliance data are **encrypted at rest with KMS**.
- Deliver logs and snapshots to **S3 with encryption**.
- Control access via **IAM policies** (`config:*`).
- Enable **multi-account aggregation** for centralized compliance.
- Use **Conformance Packs** for standardized security baselines.
- Integrate with **CloudTrail** to correlate API activity with config changes.
- Apply **least privilege** access to prevent rule tampering.

## 🔗 **Integration Patterns**

- **CloudTrail:** Track who made config changes.
- **Security Hub:** Centralized compliance findings.
- **Systems Manager Automation:** Auto-remediation workflows.
- **AWS Organizations:** Aggregated compliance reporting.
- **SNS / EventBridge:** Send alerts on noncompliant resources.
- **CloudWatch Dashboards:** Visualize compliance metrics.
- **S3:** Store snapshots and configuration history.

## 🧠 **Exam Tips**

✅ **AWS Config = compliance + change tracking.**

✅ Captures **point-in-time configurations** and **change history**.

✅ Use **Managed Rules** for quick compliance checks (e.g., encryption, tagging, MFA).

✅ **Custom Rules** use **Lambda functions** for complex checks.

✅ **Remediation actions** use **SSM documents** for auto-fix.

✅ **Aggregators** allow **multi-account / multi-Region** compliance visibility.

✅ **Conformance Packs** group multiple rules for standards like **CIS** and **PCI DSS**.

✅ Integrate with **Security Hub** for centralized dashboards.

✅ Config **does not block changes** — it only **detects and reports** them.

✅ Always enable in **all Regions** to avoid blind spots.

## 🏁 **Real-World Example**

**Scenario:**

A financial company must ensure all S3 buckets are encrypted and no security groups allow SSH from 0.0.0.0/0, with auto-remediation for noncompliant resources.

**Solution:**

- Enable **AWS Config** with recorders for all Regions.
- Apply **Managed Rules**:
    - `s3-bucket-server-side-encryption-enabled`
    - `restricted-ssh`
- Add **SSM Automation Documents** for remediation:
    - Enable encryption
    - Revoke open SSH access
- Store snapshots in **S3 (KMS-encrypted)**.
- Aggregate results across accounts in **AWS Organizations**.

**Outcome:**

Centralized compliance visibility, continuous monitoring, and automated remediation for critical security baselines.
